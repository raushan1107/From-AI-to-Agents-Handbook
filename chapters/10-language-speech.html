Part IV

Language and Speech AI

Language AI turns human communication into signals a system can classify, extract, translate or generate. Speech adds audio input and output.

In this chapterStart hereConnect the conceptConcept mapText analysis labHands-on labTrainer's takeawayQuick check

Let's make sense of it

Natural language processing covers tasks such as classification, named-entity recognition, key phrase extraction, sentiment analysis, summarisation and translation. A task-specific model may be more predictable and economical than a general-purpose LLM.

Connect the concept

Text analysis includes classification, sentiment and opinion mining, entity extraction, PII detection/redaction, language detection, translation, summarization and structured extraction. A task-specific service can be more predictable than a general model for a narrow operation; a model can help when context and flexible synthesis matter.

Speech-to-text produces a transcript; text-to-speech synthesizes audio. Voice translation may combine recognition, translation and synthesis. Real-time speech also requires streaming, low latency, turn-taking, interruption handling and a fallback channel.

Noise, accents, speed, domain vocabulary and microphones affect recognition. Word error rate is one metric, but meaning and task success matter too. Consent, privacy, retention and speaker representation belong in the design.

Hands-on lab: analyze a ticket from several angles

Goal: compare sentiment/opinion mining, entity extraction, PII detection and translation on one fictional message. Each tool answers a different question; none alone understands the complete case.

Prerequisites and data handling

Use your own Azure subscription and a Microsoft Foundry project with permission to use the Language playground, or create a supported Language in Foundry Tools resource. Usage may be billable. Use only the synthetic message below: never enter a real person’s phone number, email or customer ticket. This book supplies no credentials. See Microsoft’s PII quickstart and sentiment quickstart.

  1. Open your Foundry project. From the left pane select Playgrounds, then Try the Azure Language Playground. If that tile is absent, use the current linked setup guide to connect or create the required resource.
  2. In Sentiment Analysis, enter: The replacement arrived two days late, but the support agent was kind and helpful. Enable opinion mining if offered. Compare overall sentiment with sentence or aspect-level results. Is “mixed” more useful than a single positive/negative label?
  3. Switch to Named Entity Recognition and try: Northstar Services will contact Alex Example on 12 March 2026 about order NS-1042. Note which spans are recognized as people, organizations, dates or identifiers and which are not. NER is not a validator for every business field.
  4. Switch to PII detection and use a synthetic placeholder such as Contact demo.user@example.test about the request. Inspect detected categories and redacted text. Record whether the placeholder was detected; do not substitute a real address to improve the demo.
  5. Try translation with a short, non-sensitive sentence into a supported language. Ask a fluent speaker to review meaning, tone and domain terms before using translated text operationally.
  6. Repeat one test with negation or sarcasm, such as The package was not late; it arrived early. Explain why a confidence score does not remove the need to understand the sentence and the use case.
  7. Write a small scorecard with the task, expected behavior, observed output, failure mode and human-review condition. For automated workflows, validate structured fields and keep redacted outputs separate from original content.

Expected result

You should see that sentiment, entities and PII are separate analyses. A sensitive-data detector can miss values, and sentiment may not represent a person’s intent. Minimize the text sent, restrict access, and follow current retention and privacy requirements.

Code extension

To call these features from Python, follow Microsoft’s linked client-library quickstarts and use managed identity in hosted applications. Do not paste an API key into source code; use a secure local environment variable only for a disposable development session, or a managed identity in Azure.

Cleanup

Clear playground inputs and delete any test resources you created only for this lab. Do not preserve synthetic PII-like examples in shared logs without a reason.

Language and speech pipelines have several stages

A voice assistant is a relay race: audio capture, transcription, intent, response and speech synthesis. A baton drop at any stage can make a capable model answer the wrong question.

Inspect each stage and the whole user task. A short transcript error in a negation or number may outweigh several ordinary word errors.

Hands-on lab: synthesize and critique spoken language

Prerequisites

For text services, use your own subscription and a supported Foundry or Language resource and required permissions. API usage may incur charges. Use synthetic examples; never submit real personal information for this lab.

  1. Open the project in Microsoft Foundry, select Playgrounds → Speech playground → Text to speech. If required, create or select a supported Speech resource and choose a language and standard voice.
  2. Enter a 2–3 sentence fictional Northstar delivery update. Avoid names, addresses and real customer details. Preview the audio.
  3. Listen for pronunciation of order IDs, dates and abbreviations; note whether the rate and tone suit a customer who may be frustrated. Shorten the script if the spoken version is hard to follow.
  4. Try a second voice or adjust supported SSML prosody settings such as pause or speaking rate. Change one setting at a time and record the result.
  5. If speech-to-text is available in the playground, use a sample clip or your own recording with the speaker’s consent. Compare the transcript against what was actually said; mark names, numbers and negations that were misrecognized.
  6. Explain why transcription, language understanding, response generation and speech synthesis are separate stages. A wrong transcript can produce a polished but wrong spoken answer.
  7. Export audio only if needed for this exercise. Confirm the usage rights and retention requirements before using generated audio beyond the lab.

Expected result

A short labeled review table with sentiment/opinion, detected entities or redaction, and translation reviewed by a fluent person.

Cleanup

Delete test text, recordings and exports. Remove an exercise-only resource after checking that no shared workload depends on it.

Trainer's takeaway

Separate text analysis and speech pipeline stages; test language, noise, accents, negations and sensitive-data handling.
