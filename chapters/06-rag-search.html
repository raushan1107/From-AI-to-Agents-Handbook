RAG, Search and Grounded Answers

RAG exists because a model’s training is not the same as having access to your organisation’s latest trusted information.

In this chapterStart hereConnect the conceptConcept mapHands-on labTrainer's takeawayQuick check

Let's make sense of it

Retrieval-augmented generation combines information retrieval with generation. First, an application searches an external knowledge source. It then places selected passages into the model context so the answer can be based on those passages. This is useful for private, changing or specialised information.

Connect the concept

Ingestion turns source content into searchable records: load files, extract text and layout, clean, split into chunks, attach metadata, create embeddings where needed and index. Chunk size balances context against irrelevant material; overlap can preserve continuity while increasing index size.

At query time, keyword search is strong for exact terms and identifiers, vector search finds semantically similar passages, and hybrid search combines both. Semantic ranking or reranking can reorder candidates. Filters should respect document metadata and user access before context is sent to a model.

Supply retrieved passages with source identifiers and ask the model to answer from evidence. Preserve links and citations. Test retrieval recall and relevance separately from answer faithfulness and citation support. A fluent answer cannot use a document that retrieval never returned.

RAG improves access to current/private content but does not guarantee truth. Check freshness, extraction quality, permissions, index health, and behavior when no relevant passage exists.

RAG is a library desk beside the model

Picture a librarian finding pages before a writer drafts an answer. The search index is the catalog, retrieval is selecting relevant passages, and generation is the synthesis. If the librarian selects the wrong edition, a careful writer still starts with poor evidence.

That is why ingestion, retrieval, access filtering, citations and answer synthesis each need their own checks.

Hands-on lab: build a small grounded search experience

Prerequisites

You need your own Azure subscription and permission to create Blob Storage, Azure AI Search and a Foundry embedding deployment. Search tiers and model use can incur charges; check the linked Search quickstart for current region, tier and identity requirements.

  1. Create a dedicated resource group. In a storage account, create a private blob container and upload 3–5 short fictional policy files. Include clear headings and one policy distinction, such as “may be reviewed” versus “is guaranteed.” Do not upload confidential material.
  2. Create an Azure AI Search service at a tier that supports the tutorial’s vectorization workflow. Create or reuse a Microsoft Foundry project and deploy a text embedding model supported by the wizard.
  3. Grant the Search service’s managed identity only the required read access to the blob container, and configure the documented Search and Foundry permissions for the embedding connection. Follow the current Learn guide; do not place secrets in a document or prompt.
  4. Open the search service in the Azure portal and choose Import data. Select the blob data source and the RAG/vectorization path. Pick the container, embedding model and chunking defaults, then review the generated index fields and indexer configuration before creating them.
  5. Wait for indexing to complete. Open the indexer run history and resolve any failed documents. Inspect the index to confirm that text chunks and source metadata are present.
  6. Use Search Explorer to try an exact keyword query and a paraphrased semantic query, for example How long can a late replacement be reviewed? Compare the returned passages and relevance order.
  7. Try a question whose answer is absent. A grounded application should say the indexed evidence does not answer it instead of inventing a policy. Inspect the returned source file and chunk before trusting an answer.

Expected result

An indexed set of passages and Search Explorer results for exact and paraphrased queries. Check source text and metadata for each result.

Cleanup

Delete exercise-only indexes, storage, deployments and services, or the dedicated resource group after checking dependencies.

Trainer's takeaway

Evaluate retrieval and synthesis separately, preserve citations, and filter by user permissions before passing evidence to a model.
