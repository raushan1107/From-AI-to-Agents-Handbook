From Rules to Learning: Machine Learning and Deep Learning

The important change was moving from specifying every decision to learning useful patterns from examples.

In this chapterStart hereConnect the conceptHands-on labTrainer's takeawayQuick check

Let's make sense of it

In traditional rule-based software, a developer writes explicit instructions. In machine learning, we provide examples and a learning algorithm adjusts a model so its outputs fit patterns in the data. A trained model is the result of that process; training and inference are different phases.

Connect the concept

Supervised learning uses labelled examples, such as messages tagged as billing or delivery. Unsupervised learning looks for structure without labels, such as groups of similar requests. Reinforcement learning trains through actions and reward feedback. These are learning setups, not competing product categories.

A feature is an input signal. A delivery model might use distance, day of week and depot scan history to estimate delay. The label is the outcome it learns to predict. Deep learning is a subfield of machine learning in which multi-layer neural networks learn useful representations from data.

During training, a loss function measures prediction error; backpropagation calculates how parameters contributed to that error; an optimizer updates the parameters. Repeating this process can fit patterns, but also noise. A separate validation set helps detect overfitting. At inference time, the frozen trained model scores a new example.

More data and larger networks are not automatically better. Check data quality, leakage, class imbalance, evaluation, compute cost and what each type of mistake means to a user.

Hands-on lab: train a no-code classifier in Azure Machine Learning

Prerequisites

You need your own Azure subscription, permission to create or use an Azure Machine Learning workspace, and Azure Machine Learning studio access. Compute/training may incur charges. See the linked Microsoft Learn tutorial for current UI and requirements.

  1. In the Azure portal, create a dedicated resource group, then create an Azure Machine Learning workspace in a supported region.
  2. Open Azure Machine Learning studio, choose your subscription and workspace, then select Data and upload a small labelled CSV or use the sample dataset referenced by the official tutorial. Use data you are allowed to upload and remove personal identifiers.
  3. Preview the data. Confirm each row is one example, the header contains column names, and the target column contains the label to predict. Notice missing values and whether one label is much more common than another.
  4. Select Authoring → Automated ML → New Automated ML job. Choose Classification, select the data asset and set the label column. Name the experiment northstar-delay-classification.
  5. Choose a small CPU compute cluster with a low maximum node count and idle scale-down. Review settings, keep the experiment short and submit.
  6. When the job finishes, inspect the selected model’s validation metrics and confusion matrix. The matrix shows which classes were correctly identified and which were confused.
  7. For the important class, compare precision (how many predicted positives were truly positive) and recall (how many actual positives were found). Discuss which error costs more for your scenario.
  8. Do not deploy an endpoint for this lesson unless you have a real need and permission. An endpoint remains online and may add cost.

Expected result

A completed training job with candidate trials and validation metrics; compare performance to a simple baseline and inspect class-specific errors.

Cleanup

Delete exercise-only compute and endpoints. Delete the dedicated resource group only after checking it contains nothing you need.

Trainer's takeaway

Explain features, labels, training versus inference, and why one accuracy score can hide costly errors.
