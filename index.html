A note from the trainer

Let's connect the dots before we touch the tools.

One thing I have noticed while teaching AI is that learners can remember the name of a model or a service, but still struggle to explain why it exists. They know the word RAG, but not the problem retrieval was meant to solve. They have heard MCP, but the bigger integration story is missing. They can call an LLM API, but don't know what is happening between the prompt and the response.

So we will not learn AI as a collection of disconnected definitions. We will build one mental model at a time. When a new concept appears, we will ask three questions: What problem did it solve? How does it work? Where does it fit in the bigger picture?

And one promise: I will explain it the way I would explain it in a classroom. Simple language first. Technical depth when it becomes useful. No unnecessary complexity just to sound technical.

How to use this book
  1. Read the journey in order at least once.
  2. Pause at diagrams and explain them in your own words.
  3. Use the examples to map concepts to business problems.
  4. Open the official documentation before implementing a service.

This is a learning companion, not an official Microsoft publication or a replacement for current product documentation.

A practical distinction

AI is not one single technology.

These terms are related, but they are not interchangeable. Let's give each one a clear place.

01

Artificial Intelligence

The broad goal: build machines that perform tasks associated with intelligent behaviour, such as reasoning, perception, language or decision-making.

02

Machine Learning

A family of methods where a system learns patterns from examples instead of relying only on hand-written rules.

03

Deep Learning

Machine learning using multi-layer neural networks to learn increasingly useful representations from data.

04

Generative AI

Models that generate new content such as text, images, audio, video or code, based on learned patterns and a given context.

The running example

One business problem. Many AI building blocks.

We will keep returning to one practical scenario so the concepts never float in isolation.

Running case study · Northstar Services

A support team drowning in documents and repetitive work

Northstar has product manuals, policies, invoices, customer emails and recorded calls. Customers ask questions. Employees search for answers. Some requests need a refund, a ticket or an update in another system.

Notice how the solution grows: language understanding classifies the request; retrieval finds the right policy; a model drafts the answer; an agent can call a ticketing tool; an approval step protects sensitive actions; monitoring checks the system's behaviour.
